# UC-004: Профиль пользователя

## Trigger

Пользователь (авторизованный или гость) хочет узнать информацию об авторе поста, комментария или теме форума — либо управлять собственным профилем.

## Preconditions

- Пользователь существует в системе (`users.is_active = true`).
- Инициирующий пользователь может быть гостем (только просмотр) или авторизованным.

## Main Flow

### UC-004a: Quick-view модалка

1. Пользователь кликает на имя автора (в топике форума, комментарии к новости, header).
2. HTMX загружает `/profile/{username}/modal`.
3. Система отображает модалку: аватар/инициалы, username, статистика (посты, комментарии, последняя активность).
4. Пользователь закрывает модалку (ESC, крестик, клик вне) или переходит по кнопке «Открыть профиль».

### UC-004b: Страница профиля

1. Пользователь переходит на `/profile/{username}` (напрямую или из модалки).
2. Система отображает: аватар/инициалы, username, дата регистрации, последняя активность, счётчики постов и комментариев.
3. Если пользователь — владелец профиля, отображается форма загрузки аватара.

### UC-004c: Загрузка аватара

1. Авторизованный пользователь на своей странице профиля выбирает файл (JPEG, PNG, WebP, ≤ 5 МБ).
2. Форма отправляется автоматически (onchange).
3. Система валидирует формат и размер, сохраняет файл, обновляет `avatar_url` в БД.
4. HTMX заменяет `#avatar-block` обновлённым фрагментом с новым аватаром.

## Альтернативные и Error Flows

- **Пользователь не найден** (`GET /profile/nonexistent`): 404.
- **Не авторизован** (`POST /profile/{username}/avatar`): редирект на `/login`.
- **Чужой профиль** (`POST /profile/{other}/avatar`): 403.
- **Файл > 5 МБ**: 413, UI показывает ошибку в `#avatar-block`.
- **Неподдерживаемый формат**: 422, UI показывает ошибку в `#avatar-block`.
- **Нет аватара**: fallback — инициалы на детерминированном цветном фоне (SC-06).
- **Ошибка загрузки модалки** (5xx): страница остаётся работоспособной, модалка не открывается.

## Postconditions

- Профиль отображён корректно.
- При успешной загрузке аватара: `users.avatar_url` обновлён, файл сохранён в `storage/avatars/`.

## Scope Notes

- Удаление аватара — вне scope (NS-04 FT-024).
- Отображение аватара в header и рядом с комментариями — вне scope FT-024.
