# Memory Bank Review: консистентность и однозначность

## Задача

Провести аудит `memory-bank/` на предмет внутренних противоречий, неоднозначностей и нарушений консистентности. Не рефакторить и не исправлять — только найти и задокументировать проблемы.

## Замер времени

В самом начале работы (до чтения файлов) выполни:
```bash
date +%s > /tmp/mb-review-start
```
В самом конце (после сохранения результата) выполни:
```bash
START=$(cat /tmp/mb-review-start); END=$(date +%s); echo "$(( (END - START) / 60 ))m $(( (END - START) % 60 ))s"
```
Запиши результат в meta-блок выходного файла.

## Что искать

### 1. Противоречия
Одно и то же понятие описано по-разному в разных файлах. Примеры:
- шаги bug fix workflow в `workflows.md` vs в `create-feature-from-trello-card.md`
- Resume Protocol — одинаков ли он везде где упоминается?
- структура `run-state/` — совпадает ли описание в workflows.md и в промпте?
- условия Gate DR / Gate PR — одинаковы ли критерии во всех источниках?
- правила автономии — не конфликтуют ли `autonomy-boundaries.md` с инструкциями в `create-feature-from-trello-card.md`?

### 2. Неоднозначности
Формулировка допускает два или более разных толкования:
- «минимальный коммит», «облегчённый FT-пакет», «достаточное покрытие» — есть ли чёткое определение?
- когда именно Trello-карточку переводить в следующий статус — до или после коммита/PR?
- кто является источником истины при расхождении: `workflows.md` или `create-feature-from-trello-card.md`?

### 3. Битые/висящие ссылки
- Упоминание файла/секции, которой нет (например, `[git-workflow.md](../engineering/git-workflow.md)` — проверь что секция существует и содержит то, что ожидается)
- Ссылка на шаг/протокол без его определения в памяти

### 4. Дублирование с расхождением
- Одно и то же правило повторяется в нескольких местах, но с разными деталями (не просто копия — именно расхождение)

## Сохранение результата

Результат сохраняется в `.review-results/memory-bank/memory-bank-review-YYYY-MM-DD.md`.

Файл начинается с meta-блока:

```markdown
# Memory-Bank Review — Консистентность и однозначность

| Meta | |
|---|---|
| Дата | YYYY-MM-DD |
| Модель | <model ID, например claude-opus-4-6> |
| Время ревью | <Xm Ys — из замера> |
| Охват | <какие файлы/области проверялись> |
| Фокус | противоречия, неоднозначности, битые ссылки, дублирование с расхождением |
```

Далее — проблемы и сводная таблица в формате ниже.

## Формат вывода

Для каждой найденной проблемы:

```
### [тип: противоречие | неоднозначность | битая ссылка | дублирование]
**Файлы:** file-a.md vs file-b.md
**Суть:** одна фраза — что именно расходится
**Цитата A:** > ...
**Цитата B:** > ...
**Вопрос к владельцу:** что считать источником истины?
```

В конце — сводная таблица:

| # | Тип | Файлы | Серьёзность (high/med/low) |
|---|-----|-------|---------------------------|
| 1 | ... | ...   | ...                       |

Серьёзность:
- **high** — агент может принять неверное решение из-за этой проблемы
- **med** — неоднозначность, но контекст обычно подсказывает правильный путь
- **low** — косметика, стиль, минорные расхождения
